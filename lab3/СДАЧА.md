# Сдача лабы 3: что показывать

Новый основной сценарий переключения алгоритмов — в **[сдача2.md](сдача2.md)**. Кнопка «Для сдачи (пример)» загружает отрезок (0; 0)–(18; −15), подсветку спорных пикселей и таблицу различий. Ниже сохранён подробный сценарий с дополнительными проверками.

Запуск: `/opt/anaconda3/bin/python app.py`. Нужен только Python с Tkinter, сторонних библиотек нет.

Слева выбираешь алгоритм и параметры, фигура перестраивается сразу. Справа показаны время, исходные величины и таблица шагов. Клик по строке таблицы обводит пиксели этого шага. Колесо мыши или «−»/«+» меняют масштаб, перетаскиванием сетка сдвигается, «Вписать» показывает всю фигуру.

Если времени мало, хватит пунктов, отмеченных ★.

## 0. ★ Привязка координат к сетке (входит в 20 баллов за интерфейс)

- Скажи: «Пиксель (i, j) — квадрат 1×1 с центром в целой точке (i, j), то есть [i − 0,5; i + 0,5] × [j − 0,5; j + 0,5]. Серые линии сетки — границы пикселей, они лежат на полуцелых координатах. Серые точки — центры. Подписи осей — номера пикселей, то есть координаты центров».
- Покажи: поводи мышью по сетке. Строка внизу пишет «Курсор (3,27; 1,41) → пиксель (3; 1) = квадрат [2,5; 3,5] × [0,5; 1,5]».
- Зачем так: выбрать ближайший пиксель — то же самое, что округлить координату до целого. Концы отрезков целые, поэтому они попадают точно в центры.
- Ось y направлена вверх, как в математике. На экране y растёт вниз, поэтому при рисовании `oy − y·cell`.

## 1. ★ Один пример с вычислениями: отрезок (0; 0)–(7; 3)

Для этого расчётного примера вручную задай координаты (0; 0)–(7; 3). Переключай алгоритмы: у всех четырёх несглаженных методов получаются одни и те же 8 пикселей. Таблицы те же, что в отчёте (раздел 4). При запуске теперь открыт другой отрезок — (0; 0)–(18; −15), на котором результаты различаются.

- **Пошаговый:** k = 3/7 = 0,429, b = 0. При x = 4: y = 1,714, round = 2, пиксель (4; 2).
- **ЦДА:** L = 7, Δx = 1, Δy = 0,429, y накапливается сложением. Значения те же.
- **★ Брезенхем:** e₀ = 2dy − dx = −1, 2dy = 6, 2dx = 14. Если e ≥ 0, y += 1 и e −= 14; на каждом шаге e += 6. Пройди 2–3 строки таблицы, кликая по ним.
- **★ Окружность R = 7:** d₀ = 3 − 2R = −11. При d < 0 выбирается T, d += 4x + 6, иначе S, d += 4(x − y) + 10, y −= 1. Шесть точек октанта по симметрии дают 40 пикселей.

## 2. Все октанты и крайние случаи

- Отрезки (2; −5)–(−4; 8) (крутой, идёт влево), (5; 5)–(−5; 5) (горизонталь), (0; 0)–(0; −9) (вертикаль), (3; 3)–(3; 3) (точка).
- На крутом отрезке у пошагового алгоритма главной становится ось y. Скажи: «Если шагать только по x, отрезок распадётся на точки — рисунок 2 в отчёте».
- «Закрепить» оставляет фигуру на сетке. Удобно наложить окружности разных радиусов.

## 3. «Ничья»: (0; 0)–(4; −1)

- Пошаговый и ЦДА дают (2; 0), Брезенхем даёт (2; −1). При x = 2 точная y = −0,5, ровно на границе пикселей, поэтому оба ответа правильные.
- Если поменять концы местами ((4; −1)–(0; 0)), Брезенхем даст (2; 0): по правилу e ≥ 0 «ничья» решается в сторону конца отрезка.
- Скажи: «Автопроверка на 2601 отрезке: нарушений 0, все расхождения между алгоритмами приходятся только на „ничьи“».

## 4. ★ Время (20 баллов за отчёт)

- В приложении время пишется над таблицей. Его считает функция `measure`: повторяет построение сериями без рисования и берёт лучшую серию.
- Цифры отчёта (`python experiments.py`, M1, Python 3.13), нс на пиксель при L = 1000: Брезенхем 78, пошаговый 83, ЦДА 90, Кастл–Питвей 77, пустой цикл записи 27.
- Если спросят, почему разница всего 5–15 %, а не в разы: «В CPython любая операция над числом — это работа с объектом, порядка 10 нс. Целое сложение стоит почти столько же, сколько вещественное умножение, поэтому важно число операций, а не их тип. ЦДА медленнее пошагового, потому что округляет обе координаты, это два вызова floor вместо одного. В машинном коде отрыв Брезенхема был бы больше».
- Окружность Брезенхема в Python работает не быстрее, чем через √: корень — один вызов функции на C. На сами решения уходит 10–14 % времени, остальное — запись 8 пикселей и удаление повторов.

## 5. Доп. баллы

**★ Кастл–Питвей.** Возьми отрезок (−3; 2)–(9; −3).
- Скажи: «Отрезок в первом октанте — это строка из a ходов: s — шаг по главной оси, d — по диагонали, причём d ровно b штук. Строка строится как в алгоритме Евклида с вычитанием: x = a − b, y = b, m1 = s, m2 = d. Пока x ≠ y, из большего вычитается меньшее: при x > y m2 = m1 + перевёрнутая m2, иначе m1 = m2 + перевёрнутая m1. Ответ — (m2 + перевёрнутая m1), повторённая НОД(a, b) раз».
- На примере (7; 3) получается sdsdsds, ровно как у Брезенхема. На всех 2601 тестовом отрезке результат совпал с Брезенхемом.
- Минус: число шагов цикла доходит до a − 2 при b = 1. Строки при этом растут, и при a = 10 000 построение идёт в 23–31 раз медленнее Брезенхема.

**★ Ву (сглаживание).** Возьми (0; 0)–(7; 3), в клетках видна яркость.
- Скажи: «В каждом столбце y = [y] + f. Нижний пиксель получает яркость 1 − f, верхний — f. Сумма яркостей в столбце равна 1, поэтому толщина линии постоянна. Центр тяжести (1 − f)[y] + f([y] + 1) = y точно совпадает с прямой. y считается делением с остатком: dy·(x − x₀) = q·dx + r, f = r/dx, ошибка не накапливается».
- Рисунок 5 в отчёте: пучок отрезков без сглаживания и со сглаживанием.

## Вопросы, которые могут задать

- **Зачем 2dx в Брезенхеме?** Условие «отклонение + k ≥ 1/2» содержит дроби k = dy/dx и 1/2. Если умножить его на 2dx, всё станет целым.
- **Откуда e₀ = 2dy − dx?** На старте отклонение ε₀ = 0, а e = 2dx·(ε + k − 1/2) = 2dy − dx.
- **Откуда 3 − 2R?** Сумма D(T) + D(S) для T = (1, R) и S = (1, R − 1): D(T) = 1, D(S) = 2 − 2R.
- **Откуда 4x + 6 и 4(x − y) + 10?** Каждое из слагаемых D(T), D(S) растёт на (x + 2)² − (x + 1)² = 2x + 3, итого 4x + 6. Если y уменьшился, добавляется ещё (y − 2)² − y² = −4y + 4.
- **Почему у окружности строят только 1/8?** Окружность симметрична относительно осей и диагоналей, а на дуге от (0, R) до x = y наклон от 0 до −1, поэтому x всегда растёт на 1.
- **Почему не round() из Python?** Он округляет половины к чётному: round(2,5) = 2, round(3,5) = 4. Поэтому используется floor(y + 0,5).
- **Чем плох ЦДА?** Вещественные числа, ошибка накапливается, «ничьи» решаются случайно. На отрезках до 10 000 пикселей это ни разу не вывело пиксель за допустимую полосу.

## exe

Требуют exe для Windows или веб-приложение. Собрать на Винде: `pip install pyinstaller`, затем `pyinstaller --onefile --windowed app.py`, exe появится в `dist/`. Windows XP современный Python не поддерживает: последний Python для XP — 3.4, а в коде есть f-строки, им нужен 3.6+. Если на XP будут настаивать, придётся собирать отдельно под старый Python.
